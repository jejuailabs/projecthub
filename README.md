# Project Hub

여러 프로젝트를 수행하는 기획자가 흩어진 문서·디자인·개발·배포 정보를 연결하고, 현재 단계와 다음 행동을 파악하는 프로젝트 허브.

현재 Next.js 앱, Supabase DB/RLS, 프로젝트 관리, 회의록 추출·검토·생성을 구현 중이다. 실제 Google 로그인과 Notion 연동 검증은 남아 있다. 진행 상태는 [개발 현황](docs/13-development-status.md)을 참고한다.

## 읽는 순서

1. [최상위 구현 기준](ORCHESTRATION.md): P0/P1 범위, 기술 결정, 문서 역할.
2. [기획자 업무 모델](docs/11-planner-workflow.md): 상태·단계·담당자·다음 행동·출처.
3. [사용자 흐름](docs/02-user-flow.md): 생성부터 재진입·종료까지.
4. [텍스트 생성과 Notion 동기화](docs/10-text-notion-sync.md): 추출·검토·단계 연결·필드 방향·충돌.
5. [구현 순서](docs/08-implementation.md)와 [완료 판정표](docs/12-acceptance.md).

상세 제품/디자인/아키텍처/데이터/연동/권한/배포 문서는 [문서 목록](ORCHESTRATION.md#6-문서-체계와-우선순위)에 있다.

## 이번 명세에서 확정한 보완

- 전체 상태 5개와 업무 단계 8개 분리. 배포 없는 프로젝트도 종료 가능.
- 담당자, 다음 행동 한 개, 목표일, 대기/차단 사유와 정보 최신성.
- 필드별 기준 도구를 지정해 반복 입력을 줄이고 출처 표시.
- 회의록/텍스트 검토 생성과 단계별 Notion 연결.
- 선택 필드 동기화, 제한된 양방향, 충돌/중복/실패/복구 계약.
- 검색/필터/기본 이력 P0 통일; 팀 초대/즐겨찾기/태그/테마 편집 등 P1 분리.
- 구현 단계·실제 연동 검증·기획자 파일럿의 완료 기준 분리.

다음 작업은 Phase 0의 앱 기반 구축과 외부 연결 전제 검증이다. 실제 계정/키/호스팅 구성이 필요한 항목은 검증 결과를 기록하며, 모의 구현을 실서비스 완료로 표시하지 않는다.
