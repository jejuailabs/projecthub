# 프로젝트 자료와 랜딩 개선 — 2026-10-03

## 제품 판단

Project Hub의 중심은 여러 도구에 흩어진 프로젝트의 현재 상태와 다음 행동이다. 파일 저장 서비스나 문서 편집기를 별도로 만드는 것은 범위가 겹치고 유지 비용을 늘린다. 따라서 다음처럼 역할을 구분한다.

- **원본 링크**: Notion, Figma, GitHub 등 실제 작업 장소로 돌아가는 연결. 기존 기능을 재사용한다.
- **프로젝트 자료**: 프로젝트 판단에 필요한 회의록, 아이디어, 첨부 파일. 하나의 목록을 종류별로 필터링한다. 별도 회의록 앱·아이디어 앱을 만들지 않는다.
- **AI 검토**: 생성과 기존 프로젝트 업데이트에 같은 추출·검토 화면을 사용한다. 새 자료가 추가됐다는 이유로 프로젝트 상태를 자동 변경하지 않는다.
- **변경 이력**: 자료의 버전별 제목·분류·본문, 서버 시각, 수정자를 보존한다. 문서 협업 편집·실시간 공동 편집은 범위 밖이다.

## 구현

- 프로젝트 상세: 텍스트 및 파일 추가, 분류, 제목/본문 수정, 원본 다운로드, 버전별 이력.
- 파일은 private Supabase Storage, 파일당 최대 20MB, 한 번에 최대 5개. 로그인 사용자와 워크스페이스 권한으로 접근한다. 다운로드 URL은 60초 만료.
- 원본 파일은 덮어쓰지 않는다. 다른 파일은 새 자료로 추가하며 기존 원본을 보존한다.
- 업로드 완료 확인 전 파일은 일반 자료 목록에 표시하지 않는다. 업로드 실패 시 미완료 메타데이터가 남을 수 있으며 자동 정리는 후속 운영 작업이다.
- 프로젝트 생성: 기존 URL 입력을 파일 가져오기로 교체. TXT/MD/CSV/LOG, 텍스트 PDF, DOCX 지원. 변환 파일은 최대 4MB, PDF 50페이지, 본문 20,000자. 이미지/OCR, 스캔 PDF, 구형 DOC/HWP 변환은 지원하지 않는다. 이미지는 일반 참조 파일로 보관할 수 있다.
- 생성 화면에서 가져온 파일은 본문 추출용이다. 확정 시 추출/편집한 텍스트를 프로젝트 자료로 저장한다. 원본 파일은 프로젝트의 자료 추가에서 보관한다.
- AI는 이름 없는 아이디어에 근거 있는 제목·요약을 제안할 수 있다. 담당자·날짜·확정 사항을 임의로 채우지 않는다. 제안과 근거는 검토 화면에 표시한다.
- 원문과 후보는 초안에 암호화해 최대 24시간 보관한다. 확정 시 원문을 프로젝트 자료에 보관하고 초안 암호문을 지운다. 취소 시 초안을 삭제한다.
- 데모는 메모리에서 동작하며 실제 계정 데이터로 저장하지 않는다. 데모 AI는 고정 예시이고, PDF/DOCX 서버 변환은 로그인 후 가능하다.

## 랜딩 이미지

내장 imagegen으로 생성한 `public/planning-studio.png`를 첫 화면에 적용했다. 실제 고객이나 사무실 사진으로 오해하지 않도록 AI 생성 이미지임을 표시한다. 이미지 자체가 제품 신뢰성을 입증하지 않으므로, 실제 동작하는 데모와 미구현 연동의 준비 중 표기를 유지한다.

생성 프롬프트: 따뜻한 버터 옐로·아이보리 색감의 자연광 기획 책상. 노트, 정리된 카드, 로고 없는 노트북과 머그. 종이 질감과 부드러운 그림자의 사실적인 에디토리얼 사진. 읽을 수 있는 텍스트, 로고, 가짜 제품 UI, 인물 없음. 흩어진 생각이 계획으로 정리되는 분위기. 넓은 3:2 구도.

## 검증과 남은 경계

단위 테스트는 실제 PDF/DOCX 텍스트 추출, 파일/본문 한도, 잘못된 형식, AI 제안 근거를 검증한다. SQL 테스트는 원문 이력 보존, 이력·시각 위조 차단, 동시 수정, 보관 프로젝트 쓰기 차단, 테넌트 격리, 조회 전용 사용자의 쓰기 차단을 검증한다.

Google OAuth 설정과 로그인한 브라우저에서의 실제 파일 업로드·다운로드 통합 검증은 별도 완료가 필요하다. Notion 자동 동기화 구현 상태와는 별개이며, 이번 변경만으로 해당 연동이 완료되는 것은 아니다.

검증 결과: 단위 테스트 19개, 실제 모델 호출 2개, SQL 자료/초안 테스트 통과. 브라우저 데모에서 자료 생성·수정·v1/v2 이력 조회를 확인했다. 프로덕션 빌드 통과.

Supabase 점검에는 ERROR/WARN 없이 INFO만 있다. 비공개 사용량 테이블은 의도적으로 직접 접근 정책을 두지 않았고, 기본 키 추가는 후속 운영 개선이다. 신규 인덱스는 아직 실사용 통계가 없다. 관련 기준: [RLS 정책 없음](https://supabase.com/docs/guides/database/database-linter?lint=0008_rls_enabled_no_policy), [기본 키 없음](https://supabase.com/docs/guides/database/database-linter?lint=0004_no_primary_key), [미사용 인덱스](https://supabase.com/docs/guides/database/database-linter?lint=0005_unused_index).
