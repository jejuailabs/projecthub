# 02. 사용자 흐름

## 1. 첫 방문과 온보딩

Landing → Google 로그인 → Personal Workspace/OWNER 생성 → 언어·시간대 확인 → 프로젝트 등록 방식 선택 → 대시보드.

등록 방식은 직접 입력, 회의록/텍스트, 외부 서비스 가져오기다. 서비스 연결을 건너뛰어도 수동 프로젝트를 사용할 수 있다. 최초 화면은 샘플을 실제 데이터처럼 섞지 않으며 데모는 명시적으로 분리한다.

## 2. 세 가지 등록 흐름

### 직접 입력

이름은 필수이고 나머지는 선택이다. 상태 IDEA, 단계 DISCOVERY를 기본 제시한다. 담당자·다음 행동·기한을 간단히 추가할 수 있다. 저장 후 원본 링크/Notion 연결을 제안하되 강제하지 않는다.

### 회의록/텍스트

붙여넣기 → 선택적인 회의 날짜/원문 URL 입력 → 외부 AI 전송 안내 → 추출 요청 → 후보와 필드별 근거 검토 → 수정/제외/선택 → 생성 결과.

여러 후보를 각각 선택한다. 유사한 기존 프로젝트는 링크만 제안하며 자동 병합/수정하지 않는다. 기존 프로젝트 재연결은 별도 사용자 조작이다. 상대 날짜의 기준이 불명확하면 미정으로 둔다. 텍스트 원문은 페이지 이탈 전까지만 브라우저 메모리에 유지하며 로컬 저장소에 자동 저장하지 않는다.

### 외부 서비스 가져오기

서비스 연결 → 권한 범위 안의 후보 조회 → 항목 선택 → 기존 Project 연결 또는 새 Project 생성 → 상태/단계·Notion 속성 매핑 검토 → 가져오기 결과.

Notion 데이터베이스 전체를 프로젝트 하나로 무조건 변환하지 않는다. 데이터 소스를 선택하면 그 안의 페이지를 후보로 보여준다. 동일 소스는 같은 workspace에 중복 생성하지 않고 기존 연결을 표시한다.

## 3. 첫 화면

1. 확인이 필요한 프로젝트: 차단/기한 경과/대기/임박/정보 부족, 이유와 원본 열기.
2. 데이터 확인 필요: 동기화 실패/충돌/오래된 정보. 업무 지연과 구별한다.
3. 전체 프로젝트: 기본 List, Board/Grid 전환, 검색·필터·정렬.
4. 최근 열었던 프로젝트 최대 5개: 재개 바로가기.

요약 카운트 클릭은 해당 필터를 적용한다. 각 행은 이름, 상태, 업무 단계, 담당자, 다음 행동, 가까운 기한, 주의 이유, 출처/최신성, 원본 바로가기를 제공한다. 채워지지 않은 값은 '미정/미지정'으로 표시한다. 알림 센터나 자동 메시지 발송은 P0에 없다.

## 4. 프로젝트 상세

탭은 개요/소스/이력이다. 개요에는 업무 필드와 필드별 기준 도구·확인 시각, 다음 행동 완료, 대기/차단 해소가 있다. 외부 기준 필드는 읽기 표시와 원본 열기를 제공하고 기준 변경은 비교 화면을 거친다.

소스에는 역할(기획/디자인/실행/배포/기타), URL, 연결 계정, 동기화 상태가 있다. 이력은 사용자 변경과 가져온 활동을 구별해 20개씩 읽는다. 전체 원문이나 외부 태스크를 복제하지 않는다.

## 5. 단계와 상태 변경

Board는 기본 업무 단계 그룹이며 전체 상태 그룹으로 전환할 수 있다. 드래그와 키보드 '단계 변경' 메뉴를 함께 제공한다. 변경 확인 화면에 Notion에 반영될 필드를 표시한다. NOTION 기준 필드는 드래그 대신 원본 열기로 안내한다.

종료는 COMPLETED/CLOSED를 함께 설정한다. 재개는 두 값을 다시 선택한다. 보관은 기본 목록에서 숨기고 동기화를 정지한다. 삭제는 30일 휴지통으로 이동한다. 원본 서비스는 삭제하지 않는다. 상세 규칙은 [11](11-planner-workflow.md), [05](05-database.md) 기준이다.

## 6. Notion 연결

기존 페이지/새 페이지 선택 → 대상 데이터베이스·데이터 소스 또는 기존 일반 페이지 선택 → 속성 검증 → 필드별 기준/방향·상태/단계 매핑 → 지금 연결/지정 단계 진입 시 연결 → 쓰기 미리보기 → 설정 저장.

페이지가 이미 있으면 비교 후 baseline을 설정한다. 새 페이지는 명시한 대상에 한 번만 생성한다. 일반 페이지는 기존 페이지 제목 연결만 가능하며 자동 새 페이지 생성은 데이터 소스 대상으로 제한한다. 상세 계약은 [10](10-text-notion-sync.md).

## 7. 병합·분리

제안 보기 → 두 프로젝트/소스 비교 → 목적 Project 선택 → 업무 필드별 유지 값 및 Notion 기준 연결 선택 → 영향 미리보기 → 실행.

병합은 소스 이동이며 목적 프로젝트의 필드를 임의 덮어쓰지 않는다. 분리는 기존/새 프로젝트를 선택하고 필요한 필드를 복사할지 확인한다. 외부 쓰기 작업이 실행 중이면 종료까지 기다린다. 충돌 중이면 먼저 해결한다. 되돌리기는 버전이 맞는 경우만 허용한다.

## 8. 검색·설정·모바일

검색 대상: 프로젝트명·설명·소스명·담당자·다음 행동. 필터: 상태/단계/주의/정보 상태/서비스. 정렬: 확인 우선/기한/최근 활동/이름/생성일. 검색과 필터는 URL에 유지하고 다른 workspace 전환 시 초기화한다. 보관/휴지통은 별도 보기다.

설정: 프로필, 언어/시간대/테마, workspace 이름, 서비스 연결/재연결/해제. 팀 초대·플랜 결제·배경 편집은 표시하지 않는다.

모바일은 상태/단계 필터와 카드 리스트를 기본으로 한다. 상세는 전용 페이지를 사용한다. 사이드바는 drawer이며 복잡한 매핑·충돌 화면도 작은 화면에서 세로 비교와 저장 액션을 제공한다.
