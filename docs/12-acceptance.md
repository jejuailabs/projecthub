## 추출 평가 세트

최소 30개 fixture: 한국어 15개/영어 10개/혼합 5개. 단일·복수 프로젝트, 프로젝트 없는 메모, 모호한 날짜, 담당자 미정, 같은 이름, 텍스트 속 악성 지시문, 긴 입력을 포함한다. 기대 필드는 사람이 정의한다.

스키마 검증 후 수락된 출력은 모두 유효해야 한다. 명시적으로 존재하는 핵심 필드 정확도 90% 이상을 초기 통과 목표로 한다. 근거 없는 담당자·기한을 확정값으로 제시한 사례는 0건이어야 한다. 모델의 오류를 검토 UI에서 숨기지 않는다. 모델/프롬프트/스키마 변경 시 이 평가를 다시 실행한다.

## 릴리스 차단 결함

- 다른 workspace 정보 노출 또는 VIEWER/비인가 사용자 쓰기.
- 동의 없는 외부 페이지 생성/갱신/삭제.
- 중복 요청 또는 생성 응답 유실로 중복 페이지 자동 생성.
- 충돌을 알리지 않은 의도적 last-write-wins 덮어쓰기.
- 원문·토큰·키의 저장 정책 위반 또는 로그 노출.
- 소스/프로젝트 손실, 종료·복원 상태 불일치, 핵심 흐름 사용 불가.

외부 API의 읽기-쓰기 경합 자체를 완전 제거했다고 주장하지 않는다. 10의 제한 고지와 이력/복구 동작이 있어야 하며, 실제 손실 사례 발견 시 원인을 해결하거나 해당 방향을 차단한 뒤 재검증한다.

## 실제 기획자 시연

동일 사용자가 다음 흐름을 연속 수행한다: 회의록 후보 2개 중 1개 선택 → 담당자/기한 수정 → 프로젝트 생성 → PLANNING에서 Notion 연결 → Figma 수동 링크 → REVIEW/WAITING → 원본에서 변경 → 수신 확인 → 다음 행동 처리 → 종료.

개발 서비스가 없는 프로젝트와 GitHub/Vercel이 있는 프로젝트를 모두 시연한다. 정보 파악 시간과 추가 정리 부담은 01의 파일럿 기준으로 별도 측정한다.
