# 전체·프로젝트 캘린더와 투두

## 구현 범위

- 사이드바 전체 캘린더 / 전체 투두. 전체 보기에서 프로젝트로 필터링한다.
- 프로젝트 상세에 투두 / 캘린더 탭과 시작일·목표일 편집을 제공한다.
- 캘린더는 시작일, 목표일, 날짜 있는 할 일, 주요 포인트(마일스톤)를 표시한다. 날짜를 누르면 상세 일정이 나온다.
- 투두 추가·수정·완료·완료 취소·삭제, 기한과 대표 다음 행동 지정. 오늘·기한 초과·예정·기한 없음·완료 필터.
- 마일스톤은 날짜 필수. 완료 여부를 관리하며 기본적으로 완료 일정은 숨긴다.
- 모바일은 날짜별 일정 건수와 선택 날짜의 상세 목록을 표시한다.

## 중복 방지와 데이터

`project_plan_items` 하나를 전체/프로젝트 화면에서 공유한다. 프로젝트의 `next_action`은 대표 투두의 호환용 요약 필드다. 기존 프로젝트 편집과 AI 검토에서 다음 행동을 저장하면 같은 대표 투두가 갱신된다. 대표를 바꾸어도 이전 할 일은 삭제하거나 완료하지 않는다. 대표를 완료하면 프로젝트 다음 행동이 비워진다. 기존 다음 행동은 마이그레이션에서 투두로 옮겼다.

프로젝트 시작일은 `projects.start_date`, 목표일은 기존 `target_date`를 사용한다. 날짜는 시간 없는 YYYY-MM-DD이며 오늘 판단은 워크스페이스 시간대를 따른다. 시작일이 목표일보다 뒤일 수 없다. 날짜 없는 투두는 캘린더에 표시하지 않는다. 보관·휴지통 프로젝트는 전체 보기에서 제외하고, 상세에서 읽기만 허용한다.

변경은 프로젝트 행 잠금과 항목 버전 검증을 거친 RPC로 저장한다. 직접 테이블 쓰기를 막고 소속·역할을 검증한다. 변경 시간과 PLAN_ADDED / PLAN_UPDATED / PLAN_COMPLETED / PLAN_REMOVED 활동 이벤트를 기록한다. 항목 삭제는 soft delete이며 현재 UI에는 복구 기능이 없다. 데모는 화면 상태만 변경하며 새로고침하면 초기화된다.

## 검증 및 한계

- 단위 테스트: 달 경계·윤년, 날짜 필터, 완료/대표 제약, 시작일 순서, 데모 대표 항목 보존.
- Supabase planning/core/drafts/materials SQL 테스트 통과. 서로 다른 워크스페이스 차단, 조회 전용 역할 쓰기 차단, 버전 충돌과 보관 프로젝트 차단 포함.
- 데모 브라우저에서 전체→프로젝트 마일스톤 공유, 대표 완료 후 다음 행동 해제 확인.
- Google OAuth 설정 미완료로 실제 로그인부터 브라우저 저장까지의 E2E는 미검증.
- 외부 Google Calendar/Notion 일정 동기화, 반복 일정·시간 단위 일정·알림은 이번 범위에 포함하지 않는다.
- AI의 기존 다음 행동·목표일은 연결된다. 여러 투두/마일스톤과 시작일을 한 번에 추출하는 확장은 미구현이다.
- 여러 브라우저의 실시간 구독은 없으며 재조회로 최신 데이터를 받는다. 생성 응답 유실 후 재입력에 대한 멱등 재시도는 후속 보완 대상이다.
